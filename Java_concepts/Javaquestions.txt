## 3. Spring Memory Leak Infographic Analysis Checklist## Core Concept

* A memory leak occurs when objects are no longer needed but are still referenced. The JVM cannot reclaim this memory, leading to increased usage and eventual OutOfMemoryError.

## Common Causes, Examples, & Solutions

* Unclosed Resources: Database connections, file streams, or sessions left open.
* Solution: Always close in finally blocks or use try-with-resources.
* Static References: Static collections (like a static List) holding onto large objects.
* Solution: Avoid static collections where possible; clear them when not needed.
* Event Listeners: Listeners that are registered but not removed after use.
* Solution: Explicitly remove listeners when the associated component is destroyed.
* Cache Without Bounds: Unbounded Maps or Caches that grow indefinitely.
* Solution: Set a maximum cache size or implement an eviction policy (e.g., LRU).
* Inner Class Leak: Non-static inner classes declared inside a static context, preventing the outer class from being garbage collected.
* Solution: Use static inner classes or remove long-lived explicit references.

## 6. SQL Query Lifecycle Phases (Reference Architecture)

   1. Parser: Validates raw SQL syntax.
   2. Semantic Analyzer: Checks the existence of database elements (tables, columns, permissions, and matching data types).
   3. Optimizer: Generates the plan to execute that query in the most efficient manner (the execution planner).
   4. Execution Engine: Executes the generated plan while interacting natively with the storage engine.
   5. Storage Engine: Reads from Disk / Buffer Cache to fetch target records.
   6. Client: Rows are systematically returned back to the user client interface (psql, DBeaver, pgAdmin, App Layer).
