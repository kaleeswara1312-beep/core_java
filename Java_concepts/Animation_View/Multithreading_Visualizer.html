Side-by-Side Architecture Comparison

Deep architectural evaluation of Java intrinsic monitors vs ReentrantLock utilities.

Feature / Concept synchronized (Intrinsic Lock) ReentrantLock (java.util.concurrent)
Lock Mechanism Intrinsic Java Object Monitor (Mark Word in Object Header). Explicit Lock object backed by AbstractQueuedSynchronizer (AQS).
Acquisition & Release Automatic (implicit at block enter/exit or method boundary). Explicit via lock() and unlock() (requires try-finally).
Exception Safety Guaranteed by JVM bytecodes (monitorexit executed automatically). Manual. Missing unlock() in finally block causes permanent lock leak.
Non-blocking Try Lock Not supported. Threads block indefinitely. Supported via tryLock() / tryLock(timeout, unit).
Interruptibility Uninterruptible. Blocked threads ignore thread interrupts. Supported via lockInterruptibly(). Responds immediately to interrupts.
Fairness Selection Non-fair only. No FIFO ordering guarantees. Configurable (new ReentrantLock(true) enforces strict FIFO order).
Condition Queues Single WaitSet per object (wait()/notify()). Multiple condition objects per lock (lock.newCondition()).
