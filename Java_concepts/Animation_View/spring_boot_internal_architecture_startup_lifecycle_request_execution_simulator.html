Module 2: Deconstructing @SpringBootApplication Meta-Annotation

@SpringBootApplication is a composite annotation bundling three core configuration mechanisms. Click any node to examine its design intent.

Composite Annotation Overview

@SpringBootApplication Architecture

Serves as the primary entrypoint for Spring Boot applications. It combines configuration class semantics, automated classpath auto-configuration enablement, and package-level component scanning into a single directive.

Internal Specification & Rules:

  • Equivalent to explicitly specifying @Configuration, @EnableAutoConfiguration, and @ComponentScan.
  • Base package scanning defaults to the package containing the annotated main application class.
  • Allows disabling specific auto-configurations via exclude = {DataSourceAutoConfiguration.class}.
EQUIVALENT EXPRESSION IN RAW SPRING:
@Configuration
@EnableAutoConfiguration
@ComponentScan(basePackages = "com.example.ecommerce")
public class MyApplication { ... }

Module 3: Component Scanning vs Auto-Configuration

A side-by-side architectural comparison of application code discovery versus framework auto-configuration.

Component Scanning

Application Code

Scans user-created classes within specified base packages for Spring stereotypes (@Component, @Service, @Repository, @Controller) and registers their BeanDefinitions.

Trigger: @ComponentScan / @SpringBootApplication
Discovery Scope: Package Hierarchy (e.g. com.example.app)
Execution Timing: Early Context Refresh Phase
Conditionality: Unconditional (Unless @Conditional used)
@Service
public class OrderService {
  private final OrderRepository repo;
}

Auto-Configuration

Framework / Starters

Discovers third-party and framework configuration classes registered in imports SPI files (META-INF/spring/...AutoConfiguration.imports) and evaluates conditional annotations before creating beans.

Trigger: @EnableAutoConfiguration / AutoConfigurationImportSelector
Discovery Scope: Classpath Libraries / Starters
Execution Timing: After User BeanDefinitions Loaded
Conditionality: Highly Conditional (@ConditionalOnMissingBean etc.)
@AutoConfiguration
@ConditionalOnClass(HikariDataSource.class)
@ConditionalOnMissingBean(DataSource.class)
public class DataSourceAutoConfiguration { ... }

Module 4: Inversion of Control & Dependency Resolution

Compare traditional imperative instantiation using new versus Spring IoC container resolution.

Spring Inversion of Control (IoC)

Objects do not construct their dependencies. Instead, the Spring container inspects bean metadata, resolves required dependencies, and injects singletons into class constructors.

DI Best Practice:

• Constructor Injection: Recommended. Ensures immutability (final fields) and ease of testing.

• Field Injection (@Autowired on private fields): Discouraged. Tightly couples code to Spring container and complicates testing.

SPRING CONSTRUCTOR INJECTION CODE:
@Service
public class OrderService {
    private final OrderRepository repository;

    // Spring automatically injects OrderRepository bean
    public OrderService(OrderRepository repository) {
        this.repository = repository;
    }
}

Default DataSource Auto-Config Active

Spring Boot detects HikariCP on the classpath and confirms no user-defined DataSource bean exists in the ApplicationContext. Condition @ConditionalOnMissingBean(DataSource.class) evaluates to TRUE.

Spring Boot 3.x SPI Migration Note:

Prior to Boot 2.7/3.0, auto-configurations were loaded via META-INF/spring.factories. Modern Spring Boot 3.x uses imports list files at META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports.

EVALUATION METADATA:
@AutoConfiguration
@ConditionalOnClass({ DataSource.class, EmbeddedDatabaseType.class })
@ConditionalOnMissingBean(type = "javax.sql.DataSource")
public class DataSourceAutoConfiguration { ... }
